배포 전 필수

1. Render 무료 플랜에서는 제출된 zip 파일이 사라집니다 배포 전 필수

상황
Render 무료 웹 서비스는 디스크가 영구적이지 않아, 재배포하거나 서비스가 잠들었다 깨어나면 media/에 저장한 파일이 지워집니다. DB의 제출 기록은 남지만 파일은 없어져, 내려받기가 404(“서버 저장소가 초기화되었을 수 있습니다.”)가 됩니다.
임시 결정
적용됨 서버 로컬 파일로 저장. 전용 서버(docker-compose.prod.yml)는 media_data 볼륨이 있어 보존됩니다.
선택지
  • A. 전용 서버로 옮기기 전까지는 과제 제출을 시험용으로만 쓰고 실제 과제는 받지 않는다 (추가 비용·코드 없음) — 권장
  • B. Render에 유료 Persistent Disk를 붙인다
  • C. S3·Cloudflare R2 같은 외부 저장소를 django-storages로 연결한다 (코드 수정 필요, 서버 이전 후에도 유지 가능)

2. Vercel을 거치는 업로드에 크기 제한이 있는지 확인이 필요합니다 배포 전 필수

상황
프론트(Vercel)가 /api를 Render로 넘기는 rewrite 구조라, zip 업로드도 Vercel을 거칩니다. Vercel 프록시가 받는 요청 본문 크기에 한도가 있으면 서버 설정(50MB)과 무관하게 큰 파일이 막힙니다. 이 환경에서는 Vercel에 직접 올려볼 수 없어 확인하지 못했습니다.
임시 결정
적용됨 서버 한도 50MB(SUBMISSION_MAX_BYTES). 프론트는 서버가 413을 돌려주면 “파일이 너무 커서 서버가 받지 않았습니다.”로 안내합니다.
확인 방법
배포 후 1MB, 5MB, 20MB zip을 차례로 제출해보고 막히는 크기를 확인 → 그 크기보다 작게 SUBMISSION_MAX_BYTES를 낮추고, 앱의 안내 문구 상수 maxSubmissionBytes(frontend/lib/widgets/zip_picker.dart)도 같이 맞춥니다.
대안
업로드만 Render 도메인으로 직접 보내려면 서로 다른 도메인이 되어 CROSS_SITE_COOKIES=true와 HTTPS 쿠키 설정이 필요합니다. 전용 서버(nginx 같은 도메인)로 옮기면 이 문제는 사라집니다.

3. 배포 직후 초기 비밀번호 상태인 계정은 관리 기능과 Admin이 막힙니다 배포 전 필수

상황
서버 측 비밀번호 변경 강제가 켜지면, must_change_password=true인 계정은 운영진이라도 홈페이지에서 비밀번호를 바꾸기 전까지 마이페이지·스터디 관리·/admin을 쓸 수 없습니다. CSV나 Admin으로 만든 계정은 모두 이 상태로 시작합니다.
임시 결정
적용됨 차단 적용. createsuperuser로 만든 계정만 예외. Admin 차단 화면에 “홈페이지로 이동해 비밀번호 변경하기” 링크와 로그아웃 버튼을 둠.
할 일
배포 전 Admin → 회원 목록의 “비밀번호 변경 필요” 필터로 대상 인원을 확인하고, 운영진·스터디장에게 “홈페이지 로그인 → 비밀번호 변경”을 먼저 안내해주세요.

유지 기존 설계 그대로.
권장

  • 장기적으로는 “운영진(스터디·게시판 관리)”과 “슈퍼유저(회원·권한 관리)”를 분리하는 방안 검토
