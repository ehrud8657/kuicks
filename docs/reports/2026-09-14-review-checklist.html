A. 계정 · 초기 비밀번호 변경 강제

가상 계정은 비밀번호 변경이 끝난 상태라 강제 대상이 아닙니다. 먼저 createsuperuser 계정으로 http://localhost:8000/admin/ → 회원(Members) → 추가에서 두 계정을 만드세요: 2099100001 초기회원(정회원), 2099100002 초기운영진(운영진). 초기 비밀번호는 kuics!학번입니다.

  1. 신규 Admin 회원 추가 화면 안내 문구와, 만든 계정의 “비밀번호 변경 필요” 값을 확인한다.추가 화면에 “초기 비밀번호는 'kuics!학번'으로 자동 설정됩니다.” 안내. 목록에서 두 계정 모두 비밀번호 변경 필요 ✔
  2. 홈에서 2099100001 / 틀린 비밀번호로 로그인한다.로그인 창 안에 빨간 글씨 “학번 또는 비밀번호를 확인해주세요.” 창은 닫히지 않음
  3. 같은 계정을 kuics!2099100001로 로그인한다.로그인 직후 “비밀번호 변경” 창이 뜨고 “처음 로그인하셨네요. 계속 진행하려면 비밀번호를 바꿔주세요.” 표시. 버튼은 로그아웃 / 변경 (취소 없음)
  4. 신규 강제 창에서 바깥 어두운 영역 클릭, Esc, 브라우저 뒤로가기를 차례로 시도한다.어떤 방법으로도 창이 닫히지 않음
  5. 새 비밀번호에 규칙에 어긋나는 값을 넣고 변경을 누른다: abc!1234(9자), abcdefghij!(숫자 없음), 1234567890!(영문 없음), abcdefg1234(특수문자 없음), 확인 칸 다르게 입력.각각 “최소 10자 이상…”, “숫자를 포함해야 합니다.”, “영문자를 포함해야 합니다.”, “특수문자를 포함해야 합니다.”, “비밀번호가 일치하지 않습니다.” 메시지. 서버로 요청이 가지 않음
  6. 신규 새 비밀번호와 확인에 초기 비밀번호 그대로 kuics!2099100001을 넣고 변경한다.창 안에 “현재 비밀번호와 다른 비밀번호를 입력해주세요.” 표시, 창 유지
  7. 신규 강제 창이 떠 있는 상태로 같은 브라우저 새 탭에서 http://localhost:8000/api/me/studies/를 연다.HTTP 403, 본문에 "code": "password_change_required", “초기 비밀번호를 변경한 뒤 이용할 수 있습니다.”
  8. 신규 같은 상태에서 /api/me/, /api/semesters/, /api/boards/를 연다./api/me/는 200이고 "must_change_password": true. 학기·게시판도 200(공개 API는 그대로 열림)
  9. 신규 앱 탭으로 돌아와 브라우저 새로고침(F5)을 한다.로그인은 유지되고 강제 변경 창이 다시 뜸
  10. 신규 강제 창의 로그아웃 버튼을 누른다.창이 닫히고 로그아웃되어 홈, 상단에 Login 버튼
  11. 다시 로그인해 올바른 새 비밀번호(예: Kuics-new-2026!)로 변경한다.창이 닫히고 다시 로그인하라고 하지 않음. My Page가 정상으로 열리고 스터디 목록 로딩 오류 없음. Admin 목록에서 비밀번호 변경 필요 ✖로 바뀜
  12. 로그아웃 후 바꾼 새 비밀번호로 로그인한다.강제 창 없이 로그인
  13. 신규 다른 브라우저(시크릿 창)에서 http://localhost:8000/admin/에 2099100002 / kuics!2099100002로 로그인한다.Admin 대신 “비밀번호를 먼저 변경해주세요” 페이지(403). “초기운영진님은 아직 초기 비밀번호를…” 문구, 홈페이지 링크, 로그아웃 버튼
  14. 신규 그 페이지에서 로그아웃 버튼을 누른다.Django Admin의 “로그아웃됨” 화면이 뜨고 CSRF 오류(403 CSRF verification failed)가 없음. 다시 /admin/에 가면 로그인 화면
  15. 운영진 초기 계정으로 홈(3000번)에서 로그인해 비밀번호를 바꾼 뒤 /admin/에 들어간다.Admin 정상 진입 (새로 로그인해야 할 수 있음)
  16. 신규 createsuperuser로 만든 계정으로 홈에서 로그인한다.강제 창이 뜨지 않음. /admin/도 바로 들어가짐
  17. 로그인 상태에서 My Page → 비밀번호 변경(강제 아님)을 연다.창에 “처음 로그인하셨네요” 문구가 없고 취소 버튼이 있음. 바깥 클릭·취소로 닫힘
  18. 로그아웃한 뒤 http://localhost:8000/api/me/를 연다.403, "code": "not_authenticated", "fields": null 형식의 응답

C. 페이지 이동

스터디장 김스터디장으로 로그인해 확인합니다. 상세 화면(스터디 관리·출석 체크·제출 현황·참여자 스터디 상세)은 위에 새 화면이 쌓이는 방식이라 왼쪽 위 ← 버튼으로 돌아옵니다.

  1. 신규 상단 “스터디 관리” 버튼을 누른다.STUDY MANAGEMENT / 스터디 관리 화면. 버튼이 진한 빨강 채움 + 흰 글씨로 바뀌어 현재 위치 표시. 다른 메뉴로 가면 다시 연분홍
  2. 신규 홈 관리 패널의 “스터디 관리” 버튼, My Page 관리 패널의 버튼을 각각 누른다.둘 다 같은 스터디 관리 화면으로 이동
  3. 신규 스터디 카드 → 스터디 관리(탭 화면) → ← 버튼.상단바에 스터디 제목과 참여자/출석/과제 탭. ← 누르면 목록으로 돌아오고 목록을 다시 불러옴
  4. 신규 탭을 눌러 이동하고, 본문을 좌우로 끌어서(스와이프)도 이동한다.탭 표시(빨간 밑줄)와 내용이 함께 바뀌고 이전 탭 내용이 겹쳐 남지 않음
  5. 신규 출석 탭 → 회차 카드 → 출석 체크 화면 → 아무것도 바꾸지 않고 ←.확인 창 없이 바로 돌아오고 출석 탭 수치가 다시 불러와짐
  6. 신규 과제 탭 → 과제 카드 → 제출 현황 → ←.과제 탭으로 돌아오고 제출·미확인 수가 최신 값
  7. 신규 회차·과제 카드 오른쪽 ⋮ 버튼을 누른다.카드 안으로 들어가지 않고 수정/삭제 메뉴만 뜸
  8. 신규 정회원 홍길동 My Page → 수강 중인 스터디의 줄 → 스터디 상세 → ←.상세로 이동, 돌아오면 과제 수가 다시 불러와짐
  9. 신규 완료한 스터디 줄, 과제 제출 현황 카드의 스터디 줄도 눌러본다.둘 다 해당 스터디 상세로 이동 (가상 데이터에 완료한 스터디가 없으면 Admin에서 다른 스터디 참여를 “수료”로 하나 추가)
