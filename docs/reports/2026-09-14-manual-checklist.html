1. 자동으로 확인할 수 없는 항목

자동 점검 도구는 한글 입력기의 조합 과정, 운영체제 파일 선택창의 취소 버튼, 브라우저 자체 버튼을 흉내 낼 수 없습니다. 로컬·배포 사이트 어디서 해도 됩니다.

  1. 원본 E-16 · G-09 · K-05 아래 칸에 한글을 직접 타이핑합니다(붙여넣기 금지). 중간에 백스페이스로 몇 글자 지웠다 다시 쓰고, 여러 줄 칸에서는 Enter로 줄을 바꿉니다: 출석 체크의 메모, 회차 추가의 주제, 과제 등록의 제목·설명, 제출 현황 피드백 창의 피드백. 저장한 뒤 화면을 나갔다가 다시 엽니다.자모 흩어짐(ㅂㅓㅅ), 글자 두 번 입력, 커서가 끝·앞으로 튐, 조합 중 글자 사라짐이 없음. 다시 열었을 때 입력한 그대로 (자동 점검은 완성된 한글 입력·저장·표시만 확인)
  2. 원본 F-04 과제 등록 창에서 마감 시각을 눌러 시계 다이얼로 시·분을 바꿔 저장하고, 다음엔 수정 창에서 연필(텍스트 입력 모드)을 눌러 09:30 오전으로 입력해 저장합니다.과제 카드와 다시 연 수정 창에 고른 시각이 그대로 (예: “기한 … 09:30”). 자동 점검은 선택창이 한국어로 뜨는 것, 기본값 오후 11:59 저장, 시간대(+09:00)가 맞는 것까지만 확인

  4. 원본 H-10 참여자 스터디 상세에서 “zip 파일 제출” → 파일 선택창에서 취소.확인 창·알림이 뜨지 않고 버튼이 그대로 눌러지는 상태. 선택창 기본 필터가 zip인지도 확인
  5. 원본 C-10 스터디 관리·출석 체크·스터디 상세 같은 안쪽 화면에서 브라우저 뒤로가기(툴바 ←, Alt+←)를 누르고, Alt+→로 다시 앞으로 갑니다. 출석 체크에서 상태를 바꾼 뒤(저장 안 함) 브라우저 뒤로가기도 해봅니다. 각 화면에서 새로고침(F5)도 합니다.2026-09-14 주소 라우팅 적용 후 기대 동작: 사이트 밖으로 나가지 않고 앱 안의 이전 화면(출석 체크 → 출석 탭 → 스터디 관리 목록 → 홈)으로 돌아감. 탭을 바꾼 것은 기록에 남지 않음. 저장 안 한 출석이 있으면 “저장하지 않고 나가기” 확인 창. 새로고침해도 같은 화면·같은 탭 유지 (자동 점검에서 크롬으로 확인함 — 실제 사용하는 브라우저에서 한 번 더)

2. 배포 사이트에서만 확인할 수 있는 항목

원본 L 구역 그대로입니다. 배경은 확인이 필요한 사항 1~4번. 실제 회원 데이터가 있는 DB이므로 테스트로 만든 과제·제출물은 확인 후 지워주세요.

  1. 배포 전 운영 Admin에서 “Assignment submits” 목록이 비어 있는지 확인.비어 있음 (데이터가 있으면 배포 보류하고 알려주기)
  2. 운영 Admin 회원 목록의 “비밀번호 변경 필요” 필터로 운영진·스터디장 계정을 확인하고 비밀번호 변경을 안내.대상 인원 파악·안내 완료 (앞서 확인한 testadmin도 변경 필요 상태)
  3. Render 빌드 로그에서 migrate가 studies.0003_session_attendance_assignment를 적용.오류 없이 적용
  4. Vercel 빌드(build.sh)가 새 의존성(file_picker, flutter_localizations)으로 성공하고, 실제 사이트에서 파일 선택창이 열림.배포 성공, 선택창 열림
  5. 실제 사이트에서 1MB · 5MB · 20MB zip을 제출.어느 크기부터 막히는지 기록 (Vercel 경유 한도). 느린 네트워크에서 “올리는 중…” 표시가 끝까지 유지되는지도 확인
  6. 제출 후 Render를 재배포(또는 재시작)하고 그 파일을 내려받기.무료 플랜이면 404 “파일을 찾을 수 없습니다…” 가능성 — 결과 기록
  7. 실제 사이트(DEBUG=false)에서 /media/submissions/… 경로를 직접 연다(경로는 Render 셸에서 확인).파일이 열리지 않음(404). 권한 검사 다운로드 API로만 받을 수 있음
  8. Render Shell에서 python manage.py seed_demo 실행 시도.“운영 환경(DJANGO_DEBUG=false)에서는 가상 데이터를 만들 수 없습니다.”로 거부 (로컬 DEBUG=false에서는 확인됨)
  9. 실제 사이트에서 A(비밀번호 강제)·B(등급별 화면)와 zip 제출 한 번을 다시 확인.로컬과 같게 동작, 쿠키·CSRF 오류 없음

3. 자동 점검 중 발견한 것 — 결정 반영됨

버그는 아니지만 사용감에 영향이 있는 것들입니다. ✔ = 지금대로 둠, ✖ = 바꿔주세요(메모에 원하는 방향).

  1. 긴 제목(100~150자)이 제출 현황 요약 카드와 참여자 스터디 상세에서는 말줄임 없이 끝까지 여러 줄로 나옵니다. 목록·과제 카드·상단바는 말줄임이 정상입니다. 캡처는 자동 점검 결과에 있습니다.처리함: 제출 현황 요약 카드·참여자 스터디 상세의 제목도 3줄까지 보이고 “…” — 화면에서 한 번 보고 ✔ 해주세요. (원래 제안: 상세에서도 3줄까지만 보이고 “…” 처리. 실제 제목이 짧다면 지금대로 둬도 무방)
  2. 휴대폰 폭에서 ☰ 메뉴 서랍의 Login으로 로그인하면, 로그인 후에도 서랍이 열린 채 남습니다.처리함: 서랍에서 로그인에 성공하면 서랍이 닫히고 홈으로 이동 — 화면에서 한 번 보고 ✔ 해주세요. (원래 제안: 로그인 성공 시 서랍을 닫고 홈을 보여줌)
  3. 처음 보는 한글 글자가 아주 잠깐 네모(□)로 보일 수 있습니다. Flutter 웹이 한글 글꼴 조각을 필요할 때 구글 서버에서 받아오기 때문이며(자동 점검 첫 캡처에서 ‘눌’, ‘꿀’이 네모였다가 곧 정상), 느린 네트워크일수록 눈에 띕니다.처리함: Pretendard 글꼴을 앱에 포함 (첫 로딩 약 4.7MB 증가). 한글 글꼴을 따로 받아오지 않는 것을 자동 점검으로 확인 — 화면에서 한 번 보고 ✔ 해주세요. (원래 제안: 신경 쓰이면 한글 글꼴을 앱에 포함 — 첫 로딩 용량이 늘어남. 지금대로 둬도 기능 문제 없음)
  4. 다른 탭에서 로그아웃했거나 세션이 끝난 상태로 저장하면 알림이 “자격 인증데이터(authentication credentials)가 제공되지 않았습니다.”로 나옵니다(서버 기본 문구).처리함: 서버·앱 문구를 “로그인이 필요합니다. 다시 로그인해주세요.”로 바꾸고, 로그인 창을 이 문구와 함께 띄움 — 화면에서 한 번 보고 ✔ 해주세요. (원래 제안: “로그인이 필요합니다. 다시 로그인해주세요.”로 바꾸고 로그인 창을 띄움)
