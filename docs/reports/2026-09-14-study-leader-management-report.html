1. 한눈에 보기

  • 스터디장·운영진은 로그인하면 화면이 달라집니다. 상단 메뉴에 빨간 스터디 관리 버튼, My Page 버튼에 등급 배지, 홈과 마이페이지에 담당 스터디 요약 패널이 나타납니다. 정회원에게는 보이지 않고, 관리 API도 호출하지 않습니다.
  • 스터디장은 담당 스터디만, 운영진은 모든 스터디를 관리합니다. 이 권한은 버튼 표시와 무관하게 서버가 다시 검사합니다. 스터디장 판단은 등급 값이 아니라 실제 Study.leader 지정 여부로 합니다.
  • 관리 화면: 참여자 명단(출석 요약·출석률·제출 수·참여 상태 변경), 참여자×회차 출석 현황표, 회차별 출석 체크와 수정, 과제 등록(제목·설명·마감 날짜와 시각), 과제별 제출 현황(제출자·제출 시각·파일·미제출·지각·미확인 필터), 확인 처리와 피드백.
  • 참여자 화면: 마이페이지에서 스터디를 눌러 과제·피드백·내 출석을 보고, zip 파일만 제출합니다(최대 50MB, 재제출 시 교체).
  • 초기 비밀번호 변경을 서버에서 강제합니다. 바꾸기 전에는 로그인이 필요한 API와 /admin이 막힙니다.
  • 작업 토대로 1,923줄짜리 main.dart를 화면별 파일로 나눴습니다(동작 변화 없음).

2-3. 참여자 과제 제출 45f8b92

  • 마이페이지 수강 중인 스터디·완료한 스터디를 누르면 스터디 상세로 이동. 과제 제출 현황 카드는 기한이 남은 미제출 과제 수를 보여줍니다(“데이터 연동 예정” 자리 대체).
  • 스터디 상세: 진행 중 과제를 먼저, 마감 과제를 뒤에. 과제마다 내 제출 파일·기한 내/지각·스터디장 확인 여부·피드백, 그리고 회차별 내 출석.
  • 제출 흐름: 파일 선택 → 확장자·크기·zip 시그니처(PK) 사전 검사 → 확인 창(지각이면 지각 안내, 재제출이면 교체 안내) → 업로드 → 서버 검사(확장자 + 실제 zip 구조 + 50MB).
  • 수강 중이 아닌 참여자(수료·중도 포기)는 제출 버튼 대신 안내만 보입니다.

6. 배포할 때 해야 할 일

  • 마이그레이션: python manage.py migrate (studies.0003 — 회차·출석·과제·제출 테이블 생성, 쓰지 않던 AssignmentSubmit 테이블 삭제). Render는 빌드 명령에 포함되어 자동, 전용 서버 compose도 자동.

  • 의존성: 프론트 flutter pub get (file_picker, flutter_localizations 추가). 백엔드 추가 패키지 없음.
  • 업로드 크기: 필요하면 SUBMISSION_MAX_BYTES 설정. 전용 서버는 frontend/nginx.conf의 client_max_body_size도 같이 조정. Vercel 경유 한도는 확인 필요.
  • 파일 보존: Render 무료 플랜은 재배포·재시작 때 업로드 파일이 사라집니다 → 결정 필요.

  5. 스터디장 편의: 출석·제출 현황 CSV/엑셀 내보내기, 참여자가 제출하면 목록에 표시되는 새 제출 알림, (정책 결정 시) 스터디장이 참여자를 직접 추가.
  6. 전용 서버 이전: docker-compose.prod.yml + HTTPS + media_data 볼륨 백업 절차, CSRF_TRUSTED_ORIGINS에 포트 포함 여부 점검.
  7. 남은 골격: Activity(행사·대회), 마이페이지 “참여 행사 · 대회”, 운영진 명단 DB화.
  8. CI: README의 PR 점검 명령을 GitHub Actions로 자동 실행.

8. 개선할 점

코드

  • board_page.dart의 날짜 표기 함수가 format.dart와 중복 → 통일.
  • DRF 기본 오류 문구(“자격 인증데이터(authentication credentials)가…”)가 어색함 → 자주 보이는 코드만 한국어 문구로 덮어쓰기.
  • api_client.dart가 커지는 중 → 인증·스터디·관리 영역별로 나누기.
  • 기존 코드에도 남은 스타일(한 파일에 여러 클래스 한 줄 정의 등)을 기능 변경 시 조금씩 정리.

UX

  • 폼 다이얼로그 배경이 테마 색에 물들어 분홍빛 → 흰색으로 테마 조정 검토(기존 로그인 창도 같이 바뀜).
  • Flutter는 한국어 단어 단위 줄바꿈(keep-all)을 지원하지 않아 긴 문구가 단어 중간에서 끊길 수 있음 → 안내 문구는 짧게 유지.
  • 출석 체크 화면에 “이전 회차 상태 복사” 같은 빠른 입력 추가 가능.

테스트·운영

  • PostgreSQL에서도 테스트 실행(현재 SQLite만).
  • 실제 브라우저 E2E(로그인·업로드) 자동화. 이번에 쓴 실폰트 화면 캡처 도구는 Windows 폰트 경로를 써서 저장소에 넣지 않았습니다(frontend/test_screens/, 로컬 제외).
  • 제출 zip 내부는 검사하지 않음 → 스터디장이 받은 파일을 열 때 주의 안내, 필요 시 서버에서 압축 목록만 보여주기.
  • 로컬 개발 환경: 기본 Python 3.14는 Django 5.1 미지원 → py -3.13 -m venv .venv 권장.
