# 초기 비밀번호 변경 뒤 화면 갱신 · 저장 중 창 닫힘 수정 계획 (2026-09-15)

## 1. 초기 비밀번호를 바꿔도 오류 문구가 남는 문제

**현상 (실제 브라우저에서 재현)**
초기 비밀번호 상태로 로그인하면, 비밀번호 변경 창이 뜨는 동안 뒤 화면이 먼저 서버에 요청을 보내고 `password_change_required`(403)를 받는다.
비밀번호를 바꿔도 화면은 처음 받은 실패 결과를 그대로 들고 있어서 아래 문구가 새로고침 전까지 남는다.

- 마이페이지: 스터디장 메뉴와 수강 스터디 목록에 "초기 비밀번호를 변경한 뒤 이용할 수 있습니다."
- 홈: 스터디장 메뉴 같은 문구

**원인**
로그인 정보는 `mustChangePassword: false`로 바뀌지만, 화면 State(`initState`에서 만든 Future)는 그대로 재사용된다.

**수정**
- `AuthController`에 `passwordVersion`을 두고, 강제 비밀번호 변경이 끝나면 1 올린다.
- `RequireLogin`(스터디장 전용 화면 포함)은 화면을 `KeyedSubtree(key: 학번#passwordVersion)`로 감싼다. 값이 바뀌면 화면을 새로 만들어 다시 불러온다.
- 홈의 스터디장 메뉴(`ManagerPanel`) 키에도 같은 값을 넣는다.
- 스스로 비밀번호를 바꾸는 경우(강제가 아닐 때)는 올리지 않는다. 입력 중인 화면을 괜히 초기화하지 않기 위해서다.

## 2. 저장 중에 창이 닫혀 서버 결과가 화면에 반영되지 않는 문제

**현상**
회차 추가·과제 등록·피드백 창에서 저장을 누른 뒤 응답 전에 창 바깥을 누르거나 Esc를 누르면 창이 닫힌다.
서버에는 저장됐지만 목록이 갱신되지 않고, 같은 회차를 다시 추가하면 "이미 있습니다" 오류가 난다.
로그인 창도 같아서, 서버는 로그인됐는데 화면은 로그아웃 상태로 보일 수 있다.

**수정**
- 공통 창 틀 `AppDialog`에 `busy`를 추가한다. `busy`인 동안 `PopScope(canPop: false)`로 바깥 누르기·Esc·브라우저 뒤로가기를 막는다. 닫기·취소 버튼은 원래도 저장 중에 비활성이다.
- 회차·과제·피드백·로그인·비밀번호 변경 창이 저장(전송) 중 값을 넘긴다.
- 로그인·비밀번호 변경 창의 실패 처리에 `mounted` 확인을 넣는다.

## 확인
- 위젯 테스트
  - 강제 변경 뒤 스터디장 메뉴가 다시 불러와지는지
  - 저장 중 바깥 누르기·Esc에 창이 남고, 응답 뒤 결과를 돌려주며 닫히는지
- `flutter analyze`, 전체 테스트, 로컬 웹 빌드에서 재현 스크립트 재실행
