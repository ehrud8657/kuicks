# 스터디 진행 방식 · 일정 · 수료 요건 정보 추가 계획 (2026-09-15)

## 요청
각 스터디에 진행 방식, 일정, 수료 요건 정보를 추가한다. Docker 배포 작업은 이번 범위에서 제외한다.

## 범위
- **백엔드**
  - `Study` 모델에 `method`(진행 방식), `schedule`(일정), `completion_requirements`(수료 요건)를 추가한다. 모두 여러 줄 자유 텍스트이고 비워둘 수 있다.
  - 마이그레이션은 `0004_study_info_fields`다.
  - 공개 스터디 응답(`/api/semesters/`)에 세 필드를 넣는다.
  - Admin 스터디 편집 화면에는 자동으로 입력칸이 생긴다. 입력칸마다 예시 도움말을 붙인다.
- **프론트**
  - Study 화면의 스터디 카드를 펼치면 설명 아래에 세 항목을 보여준다.
  - 적지 않은 항목은 숨긴다.
  - 필드가 없는 예전 응답도 문제없이 열린다.
- **예시 데이터·문서:** `seed_demo`에 예시 값을 넣고, `docs/API.md` 응답 예시를 갱신한다.

## 임시 결정 (확인 필요)
- **Q-S1 입력 형식:** 스터디마다 형식이 달라 날짜·요일 같은 구조화 필드 대신 자유 텍스트로 두었다. 일정으로 달력이나 알림을 만들 계획이면 구조화 필드로 바꿔야 한다.
- **Q-S2 실제 내용:** 각 스터디의 실제 방식·일정·수료 요건은 전달받지 않아 칸만 만들었다. 운영진이 `/admin` → 스터디에서 입력한다.
- **Q-S3 운영 반영:** 마이그레이션은 빈 칸만 추가하므로 기존 데이터는 바뀌지 않는다.
  - Render는 빌드 때, 운영용 Docker는 컨테이너 시작 때 `migrate`가 자동 실행된다.
  - 그래도 운영 DB 변경이므로 반영 전에 담당자와 조율하고 백업을 확인한다.

## 확인

- Flutter 위젯 테스트

  - 빈 항목 숨김
  - 예전 응답 호환
  - 360 폭 넘침 없음
- `makemigrations --check`, `flutter analyze`, 전체 테스트
